# 🦔 Ежа — нативная игра в сообщении

## Что изменено

`/senseidaily`, «Ежа», прежние алиасы, ежедневный бонус из профиля и текстовые триггеры теперь отправляют **`sendWidget` прямо в текущий чат**, в том числе группу. Нет `WebAppInfo`, внешней кнопки запуска или перехода в личку/Mini App. Нажать на ежа для начала, гладить его нажатиями 12 секунд; последнее поглаживание после таймера запрашивает результат. Последний запрос совмещён с нажатием, поскольку **в группе widget-sandbox запрещает фоновые запросы**.

- Серверные 95% успеха / 5% неудачи, прежние награды и защита от повторного начисления сохранены.
- Успех внутри того же виджета: уведомление, фактические награды, серия и уменьшенная копия прежней картинки ежа. Исходный файл выбирается так же, как раньше, по session-токену.
- Картинка встроена как `data:` JPEG 64×64, показывается размером 96×96: внешние картинки sandbox запрещает, полный исходник не укладывается в лимит 4 KiB.
- Неудача: смешное сообщение, серия 0, без списания XP/монет. Одна попытка в день, 00:00 UTC.
- Перезагрузка виджета не меняет исход: новое нажатие возобновляет серверную сессию. Потерянный ответ можно запросить снова.
- Пересланные копии не играют (`is_shared=false`); чужой игрок не может использовать сессию владельца. Личность берётся из Telegram `widget_query.from`, не из HTML.

## Важное ограничение доставки — beta/test

Источники, проверенные при реализации:

- [widget-sandbox v0.6.0, формат доставки, раздел Bot API 10.4](https://github.com/TelegramMessenger/widget-sandbox/blob/v0.6.0/docs/tgw-format.md#the-bot-api-104)
- [Официальный conformance test-bot](https://github.com/TelegramMessenger/widget-sandbox/blob/v0.6.0/scripts/conformance/test-bot.ts)
- [SDK: запросы, ограничения по нажатию и группам](https://github.com/TelegramMessenger/widget-sandbox/blob/v0.6.0/docs/sdk-v1.md#214-requests-to-the-bot)

В upstream **указан Bot API 10.4 beta/test**: `https://api.telegram.org/beta/bot<token>/test/<method>`. Наличие методов в публичном production API и поддержка в обычном клиенте **не подтверждены**. Репозиторий sandbox сам по себе не добавляет их на сервер Telegram и не обновляет клиент пользователя.

По умолчанию бот остаётся на обычном production endpoint и пытается отправить документированный `sendWidget`. Если сервер отклоняет его/не знает метод, бот сообщает, что нативный виджет недоступен. **Попытка не расходуется, награда не начисляется, Mini App/GIF вместо виджета не подставляются.**

Для отдельного тестового бота/тестовых чатов с доступом к upstream beta:

```dotenv
TELEGRAM_WIDGET_BETA=true
```

Это **явный opt-in всего Telegram-транспорта**, включая polling: переключается endpoint на `/beta/bot…/test/…`. Не включать на обычном продакшен-боте с ожиданием, что его существующие чаты станут тестовыми. Нужны подходящий бот в тестовой среде, доступный beta API и клиент с включённым рендерингом виджетов. Настройку выполняют в секретном окружении развёртывания, не в чате и не в Git. `MINI_APP_URL` и публичный HTTPS-сайт для нативной игры не нужны.

Живой запрос в beta и отображение в реальном Telegram **не проверены**: в этой среде нет сетевого доступа к `api.telegram.org` и тестового Telegram-клиента. Успешные offline-тесты не доказывают доступность beta для конкретного бота.

## Реализация

- `src/widgets/hedgehog.py`: самодостаточный HTML, встроенные CSS/JS/картинка; `TelegramWidget.request`, без fetch/SDK Mini App и внешних ресурсов. Лимиты 32 KiB исходника / 4 KiB zlib-9 проверяются перед отправкой.
- `src/bot/native_widgets.py`: собственные классы документированных `sendWidget`, `answerWidgetQuery` до появления типизации в aiogram; ответы не более 1024 UTF-8 байт.
- `HedgehogWidgetMiddleware` обрабатывает будущие поля `widget_query`/`shared_widget_query` до стандартного диспетчера aiogram, который иначе их не распознаёт. Polling явно подписан на оба вида updates. Чужой пользователь, banned, пересылка, неправильное действие и maintenance отклоняются.
- Экономика использует существующие `HedgehogService`/`DailyService`: результат не вычисляется в JS. Атомарный user receipt предотвращает повторное начисление, включая старые Mini App-ссылки. Ограничение атомарности общего банка/журналов описано в [документации прежней реализации](HEDGEHOG_MINI_APP.md#безопасность-и-хранение).
- Старые HTTP-маршруты Mini App оставлены только для ранее отправленных ссылок; новые команды их не предлагают.

## Проверки

```bash
BOT_TOKEN=123456:TEST python -m pytest -q
BOT_TOKEN=123456:TEST python -m scripts.check_widgets
```

Настоящий QuickJS sandbox v0.6.0 проверяет четыре сценария Ежа (светлая/тёмная тема × успех/неудача), реальные gesture → request → answer, картинку, текст и отсутствие нарушений strict policy. Серверный ответ в этих тестах замокан; экономику, владельца, запреты и прохождение неизвестных updates через настоящий aiogram Dispatcher проверяют Python-тесты. Оба набора включены в CI.
