# Интерфейс карточек и Telegram widget-sandbox

## Что реализовано

- `/senseiwidget`, кнопка «🧩 Карточки» в профиле и основной клавиатуре.
- Полный профиль: звание и роль, XP / порог следующего уровня, оставшийся XP,
  монеты с дробной частью, условная оценка USDT (тот же коэффициент, что в `/mysensei`),
  билеты, сообщения, daily-серия, достижения, победы/поражения, наличие, длина,
  название, ранг и арт катаны. На максимальном уровне отображается MAX.
- Рейтинг XP, переключение и обновление через настоящие callback-кнопки.
- Анимированные GIF-карточки через существующий Bot API (`sendAnimation`).
  При ошибке GIF или отказе Telegram — PNG, затем текст с теми же кнопками. Старая команда `/mysensei` не изменена.
- Общая модель данных для PNG и самодостаточного HTML widget profile 1.
- HTML адаптируется к теме Telegram, имеет локальное скрытие/раскрытие статистики,
  не выполняет сетевых запросов и не содержит ключей, внешних ресурсов или библиотек.
- `/widgethtml` экспортирует HTML своего профиля **только администратору в личке**.
  Это исходник для тестирования, не способ отправить нативный виджет.
- Ограничения: 32768 байт UTF-8 и 4096 байт после zlib level 9; данные экранируются,
  имена ограничены, нечисловые/бесконечные значения нормализуются.
- Чужие кнопки не позволяют загрузить чужой профиль. Как и прежняя команда профиля,
  карточка, отправленная в группу, видна её участникам. Не отправляйте её в группу,
  если баланс должен оставаться личным.

По умолчанию включено. Выключить: `WIDGETS_ENABLED=false`. Старые кнопки при этом
покажут объяснение. Административный экспорт исходника остаётся доступен для тестов.
Никаких новых API-ключей или сервисов для этого режима не нужно.
Для читаемой кириллицы локально нужен DejaVu Sans; Docker устанавливает
`fonts-dejavu-core`. Pillow рендерит в отдельном потоке, одновременно не более двух
изображений. Это **снимки**: данные обновляются кнопкой, не таймером.

### Анимации

`WIDGET_ANIMATIONS_ENABLED=true` по умолчанию. Световой акцент и блик прогресса
двигаются в 12 кадрах GIF (660 px в ширину, цикл около 2 секунд). Статистика
полностью видна с первого кадра, числовые значения не меняются для декорации.
Автовоспроизведение зависит от настроек клиента Telegram. Сервер не редактирует
сообщение каждый кадр, не запускает таймеры и не требует ffmpeg. Локальный лимит
5 MiB, LRU-кэш до восьми снимков; параллельный рендер ограничен двумя задачами.

`WIDGET_ANIMATIONS_ENABLED=false` возвращает статический PNG. Обновление умеет
редактировать прежние PNG и новые animation-сообщения через `edit_media`, не
пытается вызвать `edit_text` у GIF. Текстовый fallback остаётся текстовым.
В экспортируемом HTML есть короткие CSS-анимации появления строк и прогресс-бара;
это отдельный формат, а не исполнение HTML в PNG/GIF.

## Граница интеграции: это пока НЕ нативные виджеты в сообщениях

Официальный [widget-sandbox](https://github.com/TelegramMessenger/widget-sandbox)
— клиентская среда исполнения, не Bot API-метод и не Telegram Mini App.
[Формат доставки](https://github.com/TelegramMessenger/widget-sandbox/blob/v0.6.0/docs/tgw-format.md)
описывает `inputMediaWidget` / `messageMediaWidget` через MTProto layer 233.
В используемом aiogram нет типизированного транспорта для них. Не добавлен
вымышленный `sendWidget`, `.html` не выдается за нативный media-widget,
PNG/GIF-карточка не исполняет HTML.

Для настоящей нативной доставки ещё нужно:

1. Добавить поддерживающий layer 233 бот-транспорт и тестовую среду Telegram.
2. Передавать `to_html(card)` как **несжатую** UTF-8 HTML-строку в
   `inputMediaWidget`; сжимает сервер. Размеры — anchors, caption — текстовый fallback.
3. Проверить приватные/групповые чаты и старые клиенты на реальных сообщениях.
4. Если появятся серверные действия — отдельно реализовать widget queries,
   проверку пользователя, идемпотентность и редактирование state. Текущие HTML
   намеренно read-only и не вызывают `request`, не начисляют монеты и не платят.

Фреймворк целиком не включается в production Python-контейнер: его устанавливают
клиенты Telegram. Для разработки мы используем настоящий upstream sandbox,
зафиксированный на **v0.6.0**, commit
`d6f39f3bc9a126aa418a1ac74825d84d6144183e` (не изменяемую ветку main).

## Проверка

Из корня репозитория (Python-зависимости из `requirements.txt`):

```bash
# Никакого действующего токена, MongoDB и Telegram для unit-тестов не нужно.
BOT_TOKEN=123456:TEST python -m pytest tests/unit -q

# Демо использует только вымышленные данные, не обращается к БД.
python -m scripts.widget_samples

# Node >=22, npm, git. Скачивает upstream и инструменты в игнорируемую .cache/.
python -m scripts.check_widgets
```

Последняя команда запускает HTML в **QuickJS официального sandbox**, policy `strict`,
для обеих тем. Проверяет отсутствие diagnostics валидатора, наличие render ops,
локальное скрытие/раскрытие статистики, отсутствие таймеров и действий кроме ready.
Это тест DOM shim/валидатора, **не** визуальная проверка каждого клиента Telegram
и **не** end-to-end проверка нативной доставки.

Открыть `.cache/widget-samples/*.html` можно и в официальном dev app через загрузку
HTML-файла. Обычное открытие в браузере не является проверкой изоляции sandbox.

## Файлы

- `src/widgets/cards.py` — ограниченная модель данных, HTML, PNG, проверки payload.
- `src/bot/handlers/widgets.py` — текущий транспорт, команды, callbacks, права доступа.
- `src/widgets/animation.py` — ограниченный по кадрам/размеру рендер GIF и кэш.
- `scripts/widget_samples.py` — вымышленные примеры.
- `scripts/check_widgets.py` — pinned upstream / QuickJS smoke-тест.
- `tests/unit/test_widgets.py` — безопасность данных, размеры, картинки и обработчики.

Чеки, выплаты, банк и игровые награды в рамках этой доработки не изменяются.


## Темы, движение и защита обновлений

Карточки профиля используют двухколоночные панели, рейтинг — полноширинные строки.
Длинные значения и имена переносятся по измеренной ширине шрифта до расчёта
высоты изображения; поля не отрезаются ради фиксированной высоты. PNG и GIF
используют один renderer и одну геометрию, поэтому блики не накрывают статистику
при изменении состава профиля.

Под карточкой доступны «Светлая / Тёмная» и «Без движения / Анимация».
Выбор сохраняется **в callback-кнопках конкретного сообщения**, включая переход
между профилем и рейтингом и обновление. Это не глобальная настройка пользователя.
Предыдущие ссылки `sw:<owner>:profile|top|open` продолжают работать.
Если сервер отключил анимации, переключатель движения не показывается.
Цветовую тему GIF/PNG выбирает пользователь: Bot API не передаёт тему его клиента.
HTML использует цвета и типографические токены самого клиента Telegram,
`prefers-reduced-motion` и отступ под служебную область времени сообщения.

Во время обновления одного сообщения повторное нажатие получает короткий ответ
«Карточка уже обновляется» без запроса в БД и второго рендера. Защита снимается в
`finally`, в том числе при отмене задачи. Она действует внутри одного процесса;
это не распределённая блокировка для нескольких реплик бота.

Проверка закреплена на Telegram widget-sandbox v0.6.0 (тег от 2026-11-02):
strict QuickJS, оба вида карточек, обе темы, отсутствие diagnostics. Это проверка
совместимости исходного HTML, **не** подтверждение нативной отправки или
визуальной идентичности всех клиентов Telegram.


## Кузница: `/upkatana` и «ап катана»

После **одной** завершённой попытки улучшения бот отправляет компактную карточку
760×490: имя, статус, исходная длина, фактическая разница, итог, стоимость и ранг
клинка. Успех показывает удлинение лезвия, неудача — сокращение. Числа и итог
видны с первого кадра, а изменение длины рисунка явно помечено как схематичное,
не в масштабе: прибавку 0.03 см иначе невозможно увидеть в сообщении.

Источник данных — результат `EconomyService.upgrade_katana`, дополненный
`old_length`. При неудаче у нулевой границы показывается реальная потеря, а не
полный случайно выпавший штраф (например, 0.05 → 0.00 означает −0.05 см).
Нулевое фактическое изменение не изображается как рост или сокращение.
Presenter не вызывает экономику, не делает повторной попытки и не списывает
монеты. Рендер ограничен общим semaphore с остальными карточками.

- `WIDGETS_ENABLED=false` сохраняет прежний текстовый ответ команды.
- `WIDGET_ANIMATIONS_ENABLED=false` отправляет PNG с итоговым положением клинка.
- Отказ Telegram / ошибка рендера GIF → PNG → текстовый чек с тем же итогом.
- Кнопка профиля только открывает профиль; повторного платного апгрейда в ней нет.
- Проверки наличия катаны, средств и cooldown сохранены; отклонённая попытка
  не показывает анимацию успешного роста.
- HTML-исходники успеха и неудачи генерируются `scripts.widget_samples` и
  проверяются `scripts.check_widgets` в официальном strict sandbox v0.6.0.
  В HTML движение уважает `prefers-reduced-motion`.

В Telegram по-прежнему отправляется Bot API GIF/PNG, не нативный
`messageMediaWidget`. Автовоспроизведение зависит от настроек клиента.
Новый ответ подключён к команде и её текстовым алиасам; существующий диалог
платного улучшения через кнопки `/mysensei` этой доработкой не меняется.
