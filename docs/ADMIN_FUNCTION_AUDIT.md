# Аудит административных функций

## Объём и ограничения
Проверена текущая база после PR46: каталог `/adminhelp`, регистрация команд в исходниках, существующие тесты и права нескольких административных роутеров. Это НЕ сквозная проверка всех команд в production и НЕ подтверждение корректности всех финансовых операций. Боевые начисления, блокировки, сбросы, рассылки, платежи и внешние API не запускались. Никаких изменений production MongoDB.

## Исправлено в этом PR
1. `src/bot/handlers/broadcast.py`: добавлены корневые AdminFilter для message/callback_query. Ранее callback `admin:broadcast` не имел проверки прав, а owner-проверки отдельных кнопок не заменяют проверку роли администратора. Теперь все входы FSM/кнопок закрыты для обычных пользователей, в том числе при ранее сохранённом FSM-состоянии.
2. В том же модуле добавлен отсутствовавший импорт TelegramBadRequest: исключения в обработке callback могли приводить к NameError.
3. `src/bot/handlers/boss_editor.py`: такие же корневые проверки роли на всех сообщениях/кнопках административного редактора. Игровые кнопки обычных участников находятся в других роутерах и не изменены.

Тесты проходят через aiogram router.propagate_event для запрещённых событий с контейнером без сервисов, подтверждая отсутствие вызова handler/API. Отдельно проверено, что администратор проходит root filter. Это не тест полного успешного сценария каждого редактора.

## Выявленные незакрытые риски
### Высокий приоритет: экономика
`src/services/economy_service.py`, `_get_bank_balance` и `_withdraw_from_bank`: при пустом/недостаточном банке код устанавливает начальный баланс из settings. Это противоречит требованию не создавать новую эмиссию. Process-local bank lock также не доказывает безопасность нескольких процессов. Нужен отдельный аудит всех потребителей, transactional/idempotent перенос и тесты сохранения общей суммы. В этом PR денежную логику НЕ меняли и баланс НЕ сбрасывали.

### Высокий приоритет: черновики рассылки
`src/services/broadcast_service.py` хранит единственный `_pending` в памяти; `to_confirm` и отправка из `broadcast.py` используют его без ключа администратора. Два администратора могут перезаписать черновик друг друга; рестарт теряет его. Добавленный gate защищает от обычного пользователя, но НЕ устраняет межадминскую гонку. Следующий шаг: Mongo-only черновики по admin/chat + idempotent campaign/job, атомарный claim запуска. До исправления не готовить несколько рассылок одновременно.

### Контроль доступа викторины
`quiz.py` /addquestion содержит комментарий «проверка прав опционально» и фактически позволяет обычному пользователю начать добавление вопроса в личке. Наличие команды в adminhelp не ограничивает её использование. Нужны точечные guards для административных FSM-состояний, не закрывающие обычные ответы участников. В этом PR политика викторины не менялась.

### Ограничение покрытия
AST-тест подтверждает присутствие названий в справке, но не правильность каждого описания и не работоспособность обработчика. Мок-тесты не заменяют реальную Mongo/Telegram/external API проверку. Успешный полный pytest не означает отсутствие перечисленных рисков.

## Воспроизведение
`BOT_TOKEN=123456:TEST python -m pytest -q`
`BOT_TOKEN=123456:TEST python -m pytest tests/unit/test_admin_access_audit.py tests/unit/test_admin_help.py -q`
CI отдельно поднимает disposable Mongo replica set, строит pinned MTProto runtime и запускает официальный Telegram QuickJS sandbox. Не использовать production URI для интеграционных тестов.

Локально: 533 passed, 44 skipped, 2 xfailed, 2 предупреждения существующих crypto mock-тестов. Фокус прав/справки: 27 passed. Пропущенные тесты требуют CI runtime/Mongo или специальных условий. CI результат указан в PR после завершения; live deployment отдельно.
