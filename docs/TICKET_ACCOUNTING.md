# Проверка и учёт билетов

- Каждое 300-е засчитанное групповое сообщение создаёт один билет в одной транзакции с увеличением счётчика сообщений и наградой. Уведомление показывает `code`, а не внутренний `_id`. Счётчик сообщений не является текущим балансом билетов: билеты также покупаются, выдаются и сжигаются.
- Активный билет — отдельная запись со строковым `code`, где ни `burned`, ни старый `is_burned` не равны `true`. Отсутствующий флаг допустим: так записывались старые билеты за сообщения. Любой истинный флаг означает сжигание. Это определение используют профиль, оба топа, статистика, лотерея, обмен и репозиторий.
- Розыгрыш по-прежнему допускает только держателей, состоящих в чате запуска команды. После розыгрыша или обмена оба флага сжигания устанавливаются в `true`. Кэш административной статистики может запаздывать до 60 секунд; профиль и топ читают базу напрямую.
- Старые записи викторины без `code` и с полем `amount` неоднозначны и не включаются в баланс/розыгрыш/обмен. Их нельзя автоматически превращать в билеты без аудита источника, количества и возможного расходования; новые награды викторины записываются как отдельные кодированные билеты. Само исправление не меняет исторические документы.
- БАНЗАЙ показывает подтверждённый билет только после успешного ответа сервиса; если исход выдачи не подтверждён, игроку сообщается о проверке, а не предлагается повторная выдача. Сама выдача и награда в монетах пока не составляют единую идемпотентную транзакцию.
- Транзакция не имеет ключа идемпотентности Telegram-сообщения: при повторной доставке одного update после неопределённого исхода нельзя автоматически считать, что это новое сообщение или что награда не прошла. Для прошлых случаев нужна сверка до повторного начисления.

## Сверка случая из логов

Лог `ticket_created: '6b081372915ce9571fe93a60'` для пользователя `663365714` и `messages_count: 4500` отражает успешное создание записи в результате операции; старый код возвращал MongoDB `_id`, а не код. Снимок из логов не подтверждает, что билет всё ещё активен: его могли позже обменять, сжечь или разыграть. При наличии доступа оператора к production и после проверки резервной копии достаточно **только чтения**, например в mongosh:

```javascript
db.tickets.findOne(
  { _id: ObjectId('6b081372915ce9571fe93a60'), user_id: 663365714 },
  { user_id: 1, code: 1, burned: 1, is_burned: 1, burn_reason: 1, burned_at: 1 }
)
```

Не выполнять повторную выдачу или обновление флагов без проверки текущей записи и истории её расходования. Новое определение чтения учитывает старый кодированный билет без флагов после развёртывания исправления.
