# Редкие ответы через API «Сенсей мудрец»

Существующий режим /senseifly on/off/status теперь генерирует реплики тем же AIProviderFactory и Groq, что ask_sage, вместо отправки заготовленных фраз. Нативная лаборатория /senseifly не меняется. Глобальный fly_reactions_enabled и отдельный opt-in чата сохранены, по умолчанию выключено. Команда настройки сообщает о передаче выбранного сообщения Groq. Уже включённые чаты используют новый генератор после развёртывания.

Тематического списка нет: подходят любые непустые текстовые сообщения, включая короткие, бытовые темы, ругань и обсуждение платежей. Команды, боты, пересылки и признаки контактных данных/секретов по-прежнему исключаются. API вызывается только после локального отбора, проверки прав администратора бота, ban/deleted-comment checks и Mongo reservation.

Сохранены 1.5% вероятность, 8 попыток в UTC сутки на чат, 15 минут между попытками чата и 6 часов для одного автора, защита от повторов. Лимиты и дедупликация транзакционные в Mongo. Резерв расходуется до API, в том числе при молчании/сбое, чтобы не создавать шквал запросов. Повторы доставки не запускают генерацию вновь в пределах хранения решений. Полного ответа/текста пользователя в новом журнале решений нет.

API получает только текст одного отобранного сообщения до 2000 символов, не имя, username, ID, историю или баланс. Используется настроенный GROQ_API_KEY; без ключа режим молчит. Характер — дерзкий Сенсей: сарказм, мат, резкие подколы и безвредные абсурдные советы допустимы, но не обязательны в каждой реплике. Промпт запрещает угрозы, травлю по защищённым признакам, издевательства над человеком в кризисе и опасные советы, замаскированные под шутку; не позволяет выдумывать действия бота и финансовые факты. Вход — недоверенные данные, не инструкции. Это ограничение поведения модели, не абсолютная гарантия корректности.

Ответ — строгий JSON reply:string|null. Невалидный JSON, ошибка провайдера, ссылки, разметка, пустая или длинная реплика не отправляются. Максимум 240 символов, max_tokens=220, тайм-аут 8 секунд. Перед отправкой повторная проверка доступа; reply только к исходному сообщению, без orphan fallback. Telegram send после неоднозначного исхода не повторяется. Качество/уместность модели не гарантируются; live Groq/Telegram проверка отдельно.
