# Диагностика расхождения эмиссии (только чтение)

Скрипт `scripts/diagnose_emission.py` формирует обезличенный JSON-отчёт. Он не вызывает сервисы приложения, не пересчитывает счётчик, не создаёт коллекции и не изменяет данные. В отчёте нет ID пользователей, имён, описаний транзакций или строки подключения. **Итоговые финансовые показатели всё равно могут быть чувствительными**: проверьте файл перед отправкой.

## Подготовка

- Запускайте на сервере приложения или на копии/восстановленной резервной копии БД с существующим Python-окружением проекта. Требуется установленный `pymongo` из `requirements.txt`.
- Нужна **отдельная учётная запись MongoDB с правами только на чтение** коллекций `bank`, `users` и, при запросе истории, `transactions`. Скрипт сам не проверяет права записи пользователя, поэтому ограничьте их на стороне MongoDB.
- Нужен MongoDB **5.0 или новее с поддержкой snapshot reads** (обычно replica set или sharded cluster). Скрипт выполняет все запросы в одной snapshot-сессии и завершается с ошибкой, если согласованный снимок недоступен; он не переходит незаметно к несогласованным чтениям.
- Используйте уже настроенные в окружении `MONGO_URI` и `MONGO_DB`. Не отправляйте их значения, скриншоты настроек или логи подключения. Не помещайте URI в аргументы команды или в отчёт.
- Скрипт сканирует пользователей; по умолчанию историю транзакций не сканирует. Выполняйте в период низкой нагрузки. Опциональный запрос истории может быть дорогим, особенно без индекса по дате и типу транзакций; каждая агрегация ограничена 120 секундами.

## Запуск

Из корня проекта, где окружение приложения уже содержит `MONGO_URI` и `MONGO_DB`:

```bash
.venv/bin/python scripts/diagnose_emission.py > /tmp/sensei-emission-report.json
```

Для дополнительной сводки по выбранным типам операций за последние 30 суток:

```bash
.venv/bin/python scripts/diagnose_emission.py --history-days 30 > /tmp/sensei-emission-report.json
```

Число дней от 0 до 90; интервал заканчивается временем начала диагностики, дни в UTC. После успешного выполнения проверьте файл `/tmp/sensei-emission-report.json` и пришлите его содержимое. При ошибке отчёт неполный или пустой — **не отправляйте трассировки драйвера или URI**. Сообщите только напечатанное скриптом обезличенное сообщение и версию/тип MongoDB. Файл содержит агрегаты экономики: храните его вне репозитория и удалите после передачи.

Для сравнения с предыдущими днями можно отдельно запустить тот же скрипт на каждой восстановленной резервной копии. Не запускайте его на оригинальном backup-файле и не смешивайте результаты разных копий с текущей базой.

## Как читать отчёт

- `bank_single` и `bank_main` — только числовые поля двух схем банка, без полного документа. `null` означает отсутствующее или некорректное поле, а не ноль.
- `users.numeric_balance_sum` — сумма числовых балансов, как в статистике; отдельно приведены положительные, отрицательные и нечисловые значения.
- `calculated.ui_total_supply` показывает расчёт по формуле интерфейса с ограничением компонентов снизу нулём, до округления API. `emission_minus_ui_total_supply` — разница отдельных показателей; знак важен. Если необходимых чисел нет или их тип нельзя надёжно сопоставить с преобразованием в интерфейсе (например, Decimal128), результат `null`.
- История содержит только количество и сумму по фиксированным типам операций и дням, а не записи людей. Не все операции, резервации и откаты имеют полный или единообразный журнал. Отсутствие строки не доказывает отсутствия операции.
- `duel_escrow.held_coins` — сумма двух ставок для записей `reserved` и `decided` на том же снимке; выплаченные `settled` не учитываются повторно. При некорректной ставке сумма и общий итог неизвестны. Старые дуэли без долговечной записи восстановить по этому отчёту нельзя; по одному журналу вычислить их сумму тоже нельзя.
- Один согласованный снимок может попасть между шагами операций, которые выполняются без общей транзакции. Разница сама по себе не доказывает причину и не является основанием менять балансы. Сравните несколько снимков и архивные копии; точное восстановление возможно не всегда.

## Проверка из Telegram

После развёртывания версии с этой функцией администратор может отправить боту в личном чате `/bankdiagnose`. Команда показывает только агрегированные показатели в одном снимке, не меняет данные и не выводит идентификаторы игроков. Она не устанавливает причину расхождения и не восстанавливает неполную историю. Не отправляйте ответ публично: финансовые агрегаты могут быть чувствительными.

Запрос сканирует балансы и незавершённые ставки; серверные запросы ограничены 10 секундами, вся команда — 15 секундами. При ошибке или превышении времени возвращается сообщение об отсутствии данных, не нулевые значения. В одном процессе допускается не чаще одного запуска в минуту; это не ограничение между несколькими процессами. Для подробной истории и повторной сверки доступен скрипт выше.

### Агрегаты журнала из Telegram

`/bankhistory` доступна только администратору в личном чате. Она показывает количество и подписанную сумму записей выбранных типов за последние 30 дней UTC; отдельных документов, имён и ID нет. Записи без корректной даты и невыбранные типы не включаются. Журнал может быть неполным, а запись по игроку не является полным журналом банка: нельзя выводить из этих сумм величину или причину расхождения. Финансовые агрегаты могут быть чувствительными.

Сканирование ограничено 10 секундами на MongoDB и 15 секундами на команду; при ошибке результат неизвестен. Она разделяет с `/bankdiagnose` блокировку и минутный интервал в рамках одного процесса. Ограничение не распределённое, индексы автоматически не создаются, данные не изменяются.
