# 🦔 «Погладить ежа» — Telegram Mini App

`/senseidaily`, `/daily`, «Ежа», остальные прежние алиасы и кнопка ежедневного бонуса в профиле открывают **настоящую Telegram Mini App**, а не HTML-виджет или GIF. В группе бот даёт ссылку в личный чат: Telegram разрешает `web_app`-кнопки только там.

## Правила

- Нажать «Поздороваться и погладить», гладить спинку пальцем: один раунд длится **12 секунд**.
- Сервер выбирает исход: `secrets.randbelow(100) < 95`. **95% успеха**, **5% неудачи**. Поглаживания — визуальная механика; скорость/количество жестов не добавляют скрытого шанса проиграть.
- Успех: уведомление **внутри Mini App**, одна из прежних картинок `src/infra/storage/ega`, фактически начисленные XP, монеты и серия. Базовые награды, бонусы серии и ограничение доступным балансом банка сохранены.
- Неудача: «Вы не смогли погладить ежа! Ёж включил режим кактуса…». Сбрасывается только ежедневная серия. Монеты/XP не списываются, награда не выдаётся; день считается использованным.
- Одна попытка на пользователя в календарный день UTC, обновление **00:00 UTC**. Дневной бонус, полученный до обновления бота, также блокирует повторную попытку сегодня.
- Перезагрузка/вторая вкладка не меняют исход или серверное время начала. При потере связи можно повторить запрос/открыть исходную ссылку. Таймер не запускается заново, повторного начисления нет. Закрытая игра завершается при следующем запросе результата; отдельного фонового списания/погашения нет.
- На границе UTC-дней старая ссылка становится недействительной: нужно снова вызвать `/senseidaily`.

## Настройка Render

1. Развернуть обычный **Web Service** бота с текущим `start.sh`. Существующий aiohttp-сервер на `0.0.0.0:$PORT` обслуживает и health check, и Mini App; отдельный frontend/server не нужен.
2. Указать `MINI_APP_URL=https://<публичный-домен-сервиса>` — именно базовый адрес, без `/miniapp/hedgehog`, query или fragment. На Render автоматически используется `RENDER_EXTERNAL_URL`, если `MINI_APP_URL` пустой. При reverse proxy сохранить путь `/miniapp/hedgehog` и вложенные пути на этом же сервисе.
3. Оставить обычные `BOT_TOKEN`, MongoDB и остальные настройки бота. Не передавать токен бота браузеру. Должен быть доступен официальный SDK `https://telegram.org/js/telegram-web-app.js`.
4. Проверить `https://<домен>/health` и `/miniapp/hedgehog`. Прямой переход в браузере показывает экран, но **не позволяет играть/получать награду**: нужна подписанная Telegram-сессия.
5. В Telegram: личный чат → `/senseidaily` → «Погладить ежа». Затем проверить запуск из группы и из профиля. Отдельная Main Mini App в BotFather для inline `web_app`-кнопки не обязательна; если настроена Main Mini App, не подменять её адресом без дневного session-токена.

При отсутствии публичного HTTPS бот объясняет проблему. Автоматического обхода игры с прямой выдачей награды нет.

## Безопасность и хранение

- API принимает только проверенный HMAC `Telegram.WebApp.initData` (не `initDataUnsafe`), срок до часа, допускается 30 секунд рассинхронизации в будущее. Повторяющиеся поля отклоняются. Клиентские `user_id`/`won` игнорируются.
- Непредсказуемый session-токен привязан к владельцу и UTC-дню. `_id = user_id:day` и CAS старта защищают от переброса результата. Сервер проверяет 12-секундный дедлайн.
- MongoDB `hedgehog_games`: уникальный индекс токена, TTL `expires_at` через семь дней; индексы создаются при запуске.
- Итог и изменение XP/монет/серии атомарны **в одном документе пользователя** (`hedgehog_day`, `hedgehog_result`). Это источник истины и защита от повторного начисления после перезапуска.
- Важно для эксплуатации: общий банк и вспомогательные журналы записываются после пользовательского receipt, **не в общей MongoDB-транзакции**. Сбой между этими операциями может потребовать сверки банка/журналов с receipt; ошибка журнала логируется. При конкурентном исчерпании банка его условное списание может не пройти. Это не отменяет уже выданную награду и не допускает повторного зачисления пользователю. Автоматическая финансовая сверка не реализована.
- UI/API используют один origin; размер тела запроса ограничен 16 KiB; ответы API не кэшируются. Пути картинок ограничены существующим allowlist, произвольных файловых путей API не принимает.

## Проверки

```bash
BOT_TOKEN=123456:TEST python -m pytest -q
node --check src/web/hedgehog/app.js
# Дополнительный мобильный Chromium smoke test на Linux x86_64:
npm install --prefix .cache/hedgehog-ui --no-audit --no-fund playwright-core@1.51.1 @sparticuz/chromium@133.0.0
node scripts/check_hedgehog_ui.cjs
```

Python-тесты проверяют подписи/подмену личности, 95 из 100 исходов, таймер/владельца/перезагрузку, отсутствие списаний при проигрыше, одно начисление и восстановление после обрыва записи сессии, HTTP-ресурсы/картинки/body limit и запуск в личном чате/группе. Chromium проверяет настоящий JS/DOM, жест, уведомления обоих исходов, картинку и отсутствие горизонтального overflow. SDK и API **в браузерном smoke test замоканы**; реальный запуск в Telegram и live-deploy Render проверяются отдельно.
