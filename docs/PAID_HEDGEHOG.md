# Платные повторные Ежи

## Правила

- Один бесплатный daily за UTC-сутки, как раньше.
- После него дополнительные попытки: **1, 5, 10, 20, 40, 80… Stars**. Первая платная — 1, вторая — 5, далее ×2. Цены и счётчик отдельны для каждого игрока и UTC-дня; сброс в 00:00 UTC.
- Каждая оплаченная попытка заново выдаёт полные базовые XP/монеты с бонусом уже достигнутой серии, затем открывает персональное 15-секундное окно. Серия/last_daily не увеличиваются повторно; новая бесплатная попытка на следующий день сохраняется.
- Тапы добавляют накопительные 10% от монет конкретной попытки, не сложный процент. Дополнительные монеты ограничены банком.
- Базовая платная награда — полностью либо возврат Stars: недостаток банка блокирует счёт/checkout, а если банк исчерпан после оплаты, платёж помечается для автоматического возврата без урезанной награды и без повышения цены.
- Защитный верхний предел одного счёта — 10 000 Stars; после 5120 следующая цена 10240 недоступна. Лимит не влияет на бесплатную попытку и сбрасывается с ценами на следующий UTC-день.

## Как открыть

Повтор `/senseidaily`/обычного триггера после полученного daily показывает кнопку «Ещё попытка за Stars». Счёт показывает точную текущую цену. Нельзя оплачивать следующую игру, пока текущее 15-секундное окно активно или уведомление ещё готовится. Создание счёта и отмена оплаты не повышают цену. Новый счёт нужен после смены UTC-дня.

Старый виджет не продлевается. Оплаченная новая попытка получает новый token; награда не начисляется от клика по кнопке. `/donate` остаётся отдельным пожертвованием без игровых преимуществ.

## Платежи и БД

- `paid_pet_orders`: один order ID на user/day/номер попытки; владелец, цена и snapshot награды берутся с сервера.
- Pre-checkout проверяет владельца, XTR, точную сумму, UTC-день, номер, доступность банка, ban/maintenance. Разные одновременные checkout для одного order отклоняются; lease 15 минут позволяет повтор после зависшей оплаты.
- `paid_pet_payments`: уникальный Telegram charge ID, первичная запись `received` до начисления. Повтор charge не выдаёт вторую награду. Другой charge для уже выполненного order не даёт вторую награду, а требует возврата.
- `paid_pet_days`: оплаченные и выполненные попытки каждого UTC-дня. Цена растёт после выполненного атомарного settlement, не от открытия счёта.
- **Платные** базовые награды и тапы используют MongoDB transaction: user balance + bank debit + receipt + journal + счётчик/новая сессия. При ошибке все изменения в этой транзакции откатываются.
- Требуется MongoDB replica set или mongos с sessions. Standalone: invoice/pre-checkout закрыты, без небезопасного fallback. Обычная бесплатная Ежа остаётся доступна.
- После оплаты сбой выдачи можно восстановить `/senseidaily`: `received` повторно обрабатывается; уже сохранённая pending-сессия переотправляется без второй награды и без сброса deadline. После смены суток оплаченный старый order сохраняет его номер/цену/награду, не расходует бесплатный daily нового дня. Новый платёж не заменяет активную сессию — ожидает её завершения.
- Автовозврат через `refundStarPayment`. Если Telegram недоступен, `refund_required` остаётся в журнале; пользователю предлагается `/paysupport`. Такие записи требуют операторской сверки/повтора возврата, автоматического фонового refund worker здесь нет.
- Нельзя атомарно объединить Telegram charge и MongoDB: если БД недоступна ещё до первой записи `received`, нужна сверка с Telegram `getStarTransactions`. Polling не гарантирует повторную доставку. Это эксплуатационное ограничение, не обещание exactly-once между Telegram и Mongo.

## Проверки и границы

Тесты покрывают последовательность цен, дневной сброс, полный повтор XP/coins без роста серии, повтор charge, лишний charge для того же order, запреты checkout, rollback/восстановление, общий банк и rollback paid tap. Transaction fake умеет rollback и сериализует тестовые операции; это не проверка живого replica set. Перед включением нужно проверить transaction support и реальную оплату/возврат в Telegram.

Известные гонки **старого бесплатного** settlement из `ECONOMY_AUDIT.md` остаются отдельной проблемой; новый платный путь их не наследует, но весь старый сервис не переписан этим изменением.
