# Попугай

/popugai 5 — отвечать с вероятностью 5% на каждое подходящее сообщение.
/popugai 1 — 1%, /popugai 0.5 — 0.5%, /popugai off — не отвечать.
Без аргумента — текущая настройка. Настройка доступна администраторам чата/бота.

Бот запоминает новые стикеры (включая animated/video stickers) и Telegram animation/GIF, которые получает от пользователей в группах, где сам является администратором. Коллекция отдельная для каждого chat_id. Хранятся только Telegram file_id, не файлы. Повторы дедуплицируются атомарным Mongo upsert по chat_id/type/file_unique_id; file_id обновляется. Выбор через Mongo $sample, без загрузки всей истории. Старые записи коллекции остаются доступны, без удаления или миграции.

Запоминание продолжается при выключенных ответах, off сохраняет коллекцию. Бот не скачивает старую историю чата и не видит недоставленные ему сообщения. Команды, сообщения ботов/от имени каналов, private и служебные сообщения не участвуют. Сообщения, отклонённые maintenance/moderation/subscription middleware, не участвуют. Ответы привязаны к исходному сообщению и теме; при удалении исходного сообщения отправка без reply запрещена. Текст, стикер, GIF или подпись медиа считаются подходящими сообщениями. Медиа может использоваться сразу после запоминания. При пустой коллекции ответов нет.

Процент — вероятность на сообщение, не точная квота; при 100% бот отвечает на каждое подходящее сообщение, отдельного cooldown нет. Сбои Mongo/Telegram не блокируют остальные обработчики, нет локальной очереди/повторных отправок. Ограничения отправки стикеров/GIF со стороны Telegram могут помешать ответу. Удаление накопленной коллекции не добавлено.

Раньше 1 ошибочно означало 100%, теперь ввод всегда в процентах. Уже сохранённые настройки не пересчитываются: нужный процент задайте командой снова.

Перед отправкой Mongo popugai_decisions резервирует chat_id/message_id на 7 дней (TTL). Это at-most-once попытка: сбой после резервации может оставить сообщение без ответа; неоднозначные отправки не повторяются. Попытка Попугая подавляет ИИ-ответ на то же сообщение в этой обработке. Старые документы настроек обновляются по их существующему _id для совместимости с unique chat_id индексом.
