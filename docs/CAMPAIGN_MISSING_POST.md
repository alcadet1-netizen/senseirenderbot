# Удалённый/недоступный пост розыгрыша

Telegram Bot API не доставляет универсальное уведомление об удалении поста/сообщения. Поэтому нельзя обещать немедленное обнаружение каждого ручного удаления. Наблюдаемые сигналы: сохранённое ботом удаление (campaign_deleted_messages) или явный отказ Telegram `message to be replied not found` / `reply message not found` при отправке к корню обсуждения. Отказ означает недоступность reply target, не обязательно доказывает удаление именно канального поста.

До начального объявления: существующий lease-owner сохраняет кампанию как cancelled, terminal=true, sealed=true, cancellation_reason=announcement_reply_target_missing. Это штатная INFO запись, без traceback и без отправки отдельного сообщения в общий чат. Кампания больше не выбирается воркером, не принимает комментарии и не создаёт финансовый план/награды. Tombstone позволяет избежать даже первого запроса Telegram.

Это распространяется на старые записи в phase=announcement со статусом failed/active: после обновления воркер при следующей разрешённой попытке обработает отказ штатно. Массовая миграция/удаление записей и reset Mongo не требуются. Если уже истёк срок объявления, применяется прежнее terminal завершение по deadline.

После состоявшегося объявления/выплат сохраняется прежняя логика: финал пытается ответить корню, при отсутствии — обновить своё объявление. Если и оно недоступно, доставка помечается blocked/terminal (WARNING, без traceback для известных ответов Telegram), уже обработанный план и деньги не откатываются, не выдаются повторно. Нельзя автоматически отменять уже начисленные награды из-за исчезновения публикации.

Иные BadRequest и транспортные сбои не классифицируются как удаление: сохраняется retry/диагностика. Никакого fallback с allow_sending_without_reply=true, незаметного перевода уведомлений в общий чат или повторного начисления.

Общие CampaignCases запускаются локально с fake Mongo и в CI с настоящим replica set. Добавлены сценарии missing root до объявления, restart/no retry/no rewards, известный tombstone без API вызова и unrelated BadRequest с сохранением retry. Существующие final recovery/no-double-payout тесты сохраняются. Реальные посты и production Mongo тестами не изменяются.
