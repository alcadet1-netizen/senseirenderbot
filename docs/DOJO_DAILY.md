# Dojo: ежедневная серия и сундуки

Сервер использует календарные дни UTC. Игрок вручную получает награду один раз в день: 1-й день — 100 Coin, 2-й — 200, 3–90-й — 600. Пропущенный день и день после завершения 90-дневной серии начинают серию заново. На 7, 14, 21 и каждом следующем кратном семи дне выдается соответственно 1, 2, 3 и далее бонусных сундука. Неиспользованные бонусные сундуки сохраняются при сбросе серии. Один дополнительный сундук доступен бесплатно каждый день UTC; бесплатный расходуется раньше бонусных и не накапливается.

Все шансы фиксированы (цифры ниже предназначены для документации; в окне игрока проценты не отображаются): 99% на Coin (100, 200, 300, 400, 500 — по 19,8% каждый) и 1% на виртуальные GRAM (0,01, 0,02, 0,03 — по 1/3 от 1%). Шанс не зависит от баланса или серии. Виртуальный баланс GRAM хранится целыми сотыми; он не является выплатой реального актива. Вывод не реализован, кнопка отключена. 1 GRAM, 3 GRAM и NFT в ленте пока только декоративные: сервер не выбирает и не выдаёт их. Карточки 1 и 3 GRAM оформлены как остальные GRAM-призы для будущего подключения механики.

Coin выплачиваются из SenseiBank в той же MongoDB-транзакции, что и запись серии или открытие сундука; необходим MongoDB replica set с поддержкой транзакций. Сундук доступен только когда в банке есть минимум 500 Coin, чтобы все возможные Coin-призы были обеспечены. При нехватке средств серия/сундук не расходуется. Повтор открытия с тем же идентификатором возвращает прежний результат. Анимация показывает полученный сервером результат; она не выбирает награду. Для проверки в реальном окружении нужны MongoDB-транзакции и Telegram initData; юнит-тесты с моками не заменяют проверку гонок и восстановления после сбоя.

## Выдача администратором

`/addchance @username 10` добавляет 10 бонусных сундуков зарегистрированному пользователю. Доступно только администраторам бота; количество за команду — 1–10000. Username ищется без учёта регистра, при нескольких совпадениях операция отклоняется. Сундуки и аудиторская запись (`dojo_admin_chest_grants`, id админа/игрока/сообщения) записываются в одной MongoDB-транзакции; повторная доставка того же Telegram-сообщения идемпотентна. После неопределённой ошибки проверьте журнал, прежде чем отправлять новую команду: новое сообщение имеет новый id и может выдать сундуки повторно. MongoDB должна поддерживать транзакции.
