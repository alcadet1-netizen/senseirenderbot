# Панель администратора Dojo

## План и реализация

1. Доступ к панели и каждому административному API определяется сервером по проверенному Telegram initData и `settings.admin_ids`. Скрытие кнопки в интерфейсе не является проверкой прав.
2. В профиле доступны создание и редактирование задания, включение/отключение, название, тип и адрес. ID задания при изменении сохраняется: уже получившие награду пользователи не могут получить её снова. Для канала бот должен быть администратором; подписка проверяется через Telegram. Для HTTPS-ссылки фактическое выполнение или регистрация во внешнем приложении **не проверяются**.
3. Награда нового или отредактированного задания: Coin, разовая энергия, внутренние сотые GRAM и бонусные сундуки. Они начисляются с отметкой о получении в одной транзакции MongoDB. Coin списываются из SenseiBank; энергия не меняет постоянный максимум. GRAM — существующий внутренний баланс, а не реальная выплата: вывод пока не реализован. Включение реальных выплат требует отдельной серверной интеграции.
4. Форма выдачи сундуков ищет зарегистрированный `@username` без учёта регистра, отклоняет неоднозначные совпадения и использует существующий транзакционный журнал `dojo_admin_chest_grants`. Идентификатор выдачи сохраняется в текущей вкладке браузера для повторной отправки после ошибки. После закрытия вкладки перед повторной выдачей нужно проверить журнал.
5. Для атомарной выдачи требуется MongoDB с поддержкой транзакций (replica set). Старые неизменённые задания сохраняют прежнюю механику; после редактирования через панель используют новую транзакционную схему. Данные о полученных ранее заданиях сохраняются.

Проверки подписки и подключения внешних приложений, работу интерфейса в Telegram WebView, конкуренцию начислений и восстановление после сбоев необходимо проверить в реальном окружении. Тесты с моками не являются проверкой MongoDB replica set.
